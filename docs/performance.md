# 0.6.0の性能測定

2026年10月26日に、0.5.0の配布EXEと0.6.0のARM64リリースビルドを同じ端末で比較した。
実装の目的は、起動時の直列処理と、筆記・設定変更時の待ちを減らすこと。

## 変更と確認

- Inkの初期化をツールバー作成より先に開始し、専用スレッドで並行して実行する。
- 通常起動ではログ用ファイルを開かず、書式化用の引数も評価しない。
  診断時のストローク数の書き込みはUIスレッドへ移した。
- 追加・消去イベントの画数で件数を更新する。毎回 `StrokeContainer().GetStrokes()` を呼ばず、
  読み込み時に件数のキャッシュも復元する。
- 設定保存を専用ワーカーへ移した。ワーカーは最初の設定変更時に作成し、
  連続した変更をまとめ、終了時には最後の設定を書き終える。
- 同じ画面サイズや設定への変更要求を省く。
- リリース設定を `opt-level = "s"`、`lto = "fat"`、`codegen-units = 1` とした。
  ネイティブAPIを呼ぶ本体のサイズを抑え、Windows Inkが筆跡を描画する構成を維持した。

Windows Inkは入力中の描画を低遅延のバックグラウンドスレッドで処理する。
アプリ側のイベント処理では追加のディスク処理を避ける。
仕様の参照先: [Microsoft Learn: StrokesCollected](https://learn.microsoft.com/en-us/uwp/api/windows.ui.input.inking.inkpresenter.strokescollected)。

## 条件

- Windows ARM64、OSバージョン10.0.26300。
- Snapdragon X Plus（8-core、3.30 GHz）。
- Rust 1.98.1、MSVC ARM64、VC++ランタイムの静的リンク。
- 空のノートを新しいプロセスで起動。設定は測定専用の `LOCALAPPDATA` に分離した。
- 両版を交互に11回ずつ起動。最初の各1回をウォームアップとして除外し、各10回を集計した。
- 0.6.0は `MIONOTE_DIAGNOSTICS=1` を指定。0.5.0も常時ログが有効なため、
  両版でログ内の `Windows Ink ready` の時刻を比較した。
- 自動測定のウィンドウは非表示。Inkの準備後200msにメモリと累積CPU時間を採取し、
  測定用の空のプロセスだけを停止した。ファイルの読み込み・保存や手書き入力は含まない。

## 結果

| 指標 | 0.5.0 | 0.6.0 |
| --- | ---: | ---: |
| EXEサイズ | 705,536 bytes（689 KiB） | 655,360 bytes（640 KiB） |
| Ink準備時間の中央値 | 51.5 ms | 40.7 ms |
| Ink準備時間の範囲 | 44–60 ms | 30.4–45.1 ms |
| プライベートメモリの平均 | 3.89 MiB | 3.90 MiB |
| ワーキングセットの平均 | 22.62 MiB | 22.61 MiB |
| スレッド数 | 6 | 6 |
| 起動後の累積CPU時間の平均（参考） | 50.0 ms | 56.3 ms |

EXEサイズは約7.1%、ログ内のInk準備時間の中央値は約21.1%減少した。
起動直後のメモリ使用量はほぼ同じだった。CPU時間は短い区間で量子化されるため参考値とする。

生データは [performance-20261026.csv](performance-20261026.csv) に保存した。
`Warmup=True` の行は集計から除外した。
`LaunchToObservedReadyMs` はPowerShellから起動してログを検出するまでの時間で、
プロセス生成、ファイル監視、ポーリングの待ちも含む補助値である。

比較したEXEのSHA-256:

```text
0.5.0: dc7ff429727d8ffa1e33f4371344f0c0586799426f333fe9cb2c57458edcce07
0.6.0: df7ac84efa713610ce83fcf4453ba202d72144c682153cebe1e50238db690696
```

## 測定の範囲

Ink準備時間はRustの `main` 開始からInkホストの準備完了までの時間。
OSがEXEを読み込む時間、ウィンドウの最初の表示、ペン先から画面表示までの遅延は含まない。
コールド起動・実ペンの筆圧・120Hz表示・長時間筆記・大量の筆跡の性能は別途確認が必要。
高速な筆記で線が欠ける既知の現象について、この変更での解消は未確認。

自動テスト10件で、設定の保存・復元と失敗時の保持、非同期保存中の次の設定変更、
終了直前の最終設定の保存、ZIP/JSON、ISFの筆圧・描画属性、DPI補正、再保存を確認した。
マウス操作では描画、画数更新、日本語名での保存・再読み込み、読み込み後の追記・再保存、
筆圧設定の切り替えと保存を確認した。
