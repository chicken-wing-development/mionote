# PDF・PNG・SVGの書き出し

0.8.0は「書き出し ▾」から5種類の出力を選べます。
PDFは全ページ、PNGとSVGは現在のページです。PNG・SVGの全ページ出力はZIPを使います。
ZIP内はpage-0001.png / page-0001.svgなどの順で、空白ページも含めます。

PNGは300dpiです。A4縦は2480×3508 px、JIS B4縦は3035×4299 pxです。
PNGの解像度情報も300dpiとして記録します。画素数の丸めで実寸に1画素未満の差が生じます。
SVGは幅と高さをmm、viewBoxを96dpiのDIPで設定します。筆跡・罫線はベクターです。
白い背景を使い、用紙の外へは描画しません。透明背景は現在は選べません。

描画はPDF・PNG・SVGともdrawing.rsを使います。
Windows Inkの描画セグメントに既に反映されたPointTransformを二重適用しません。
筆圧ありの線は幅として近似します。元の筆圧・筆点を編集できる形式は.inknoteです。
書き出してもノートの保存先・変更状態は変わりません。

## 軽量性と保存

PNGはWindows標準のGDI+をSystem32から出力時だけ読み込みます。
PNG出力を使わない起動・筆記・SVG/PDF出力では初期化しません。
PNG ZIPも画像バッファは1ページずつ作成・解放します。
SVGとPDFはパスを書き出し、大きなページ全体のビットマップを作りません。
ファイル・ZIPは一時ファイルへ完成させ、成功後に保存先へ置き換えます。
0.11.0以降は書き出し全体に512 MiB・200万描画コマンドの上限を設けます。失敗時は以前の保存先を保持します。

## 確認

Windows ARM64で15件の自動テストが通過しました。
4種類の用紙×縦横と空白ページをPNG/SVGへ出力し、ZIPの順序・欠落がないことを確認しました。
独立した画像・XMLパーサーでPNGの画素数・300dpi、SVGのmm寸法、筆跡の座標と線幅を検証しました。
別のSVG描画処理で画像化した結果もPNGと同じ筆跡位置・幅になり、画像を視覚確認しました。
PNGレンダラーが起動時のDLL依存へ含まれないことをEXEの依存情報で確認しています。
既存の全ページPDFと新形式ノートの保存・読み込みもテストしています。
